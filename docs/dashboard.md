# Dashboard

## Overview

The Monitoring Dashboard provides operational visibility into telemetry activity, security alerts, attack simulations, and overall platform health within the Secure Distributed ICS Security Platform.

The dashboard serves as the primary interface for observing system behavior, reviewing security events, and monitoring telemetry generated by distributed sensor nodes.

The dashboard is implemented using Streamlit and is designed to simulate a Security Operations Center (SOC) style monitoring console for industrial control system (ICS) environments.

---

# Purpose

The dashboard was developed to:

* Monitor telemetry activity in real time
* Display security alerts generated by the Detection Engine
* Visualize attack simulation events
* Provide operational visibility into platform health
* Centralize security event monitoring
* Support security analysis and validation activities

---

# Dashboard Architecture

The dashboard consumes information from multiple platform components.

## Data Sources

### Telemetry Data

Source:

```text
logs/telemetry.json
```

Provides:

* Temperature readings
* Pressure readings
* RPM values
* Sensor identifiers
* Timestamps

---

### Security Event Logs

Source:

```text
logs/system_logs.txt
```

Provides:

* Authentication failures
* Replay detections
* Anomaly alerts
* Tampering alerts
* Flooding attack events

---

### Detection Engine

Source:

```text
security/anomaly_detection.py
```

Provides:

* Alert generation
* Severity classification
* Behavioral anomaly detection
* Threshold violation detection

# Dashboard Components

## System Overview

Displays high-level platform metrics including:

* Active sensors
* Alert count
* Threat event count
* Overall system health

---

## Telemetry Monitoring

Displays current telemetry values generated by sensor nodes.

Monitored values include:

* Temperature
* Pressure
* RPM
* Sensor status

Future versions will include telemetry trend visualization.

---

## Security Alerts

Displays security events generated by the Detection Engine.

Alert severities include:

* LOW
* MEDIUM
* HIGH
* CRITICAL

---

## Attack Activity

Displays detected adversarial simulation activity.

Supported attack categories include:

* Sensor spoofing
* Replay attacks
* Telemetry tampering
* Flooding attacks
* Unauthorized node access

---

## Security Event Viewer

Displays recent security events from centralized logging.

The event viewer enables operators to quickly review platform activity and identify abnormal behavior.

---

# Monitoring Workflow

1. Sensor nodes generate telemetry
2. Security Gateway validates telemetry
3. Detection Engine analyzes telemetry behavior
4. Security alerts are generated when anomalies are detected
5. Events are written to centralized logs
6. Dashboard retrieves telemetry and event data
7. Operators review telemetry and security activity
